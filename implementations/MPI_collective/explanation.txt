8. MPI: коллективные операции

ФАЙЛЫ

КАК РАБОТАЮТ КОЛЛЕКТИВНЫЕ ОПЕРАЦИИ MPI
Запускаются 9 отдельных процессов через mpiexec -n 9.
MPI_Init инициализирует MPI. rank — номер процесса, count — число процессов.
В MPI_COMM_WORLD участвуют все девять. Процесс 0 тоже перебирает свою часть.
Ввод выполняет только процесс 0, остальные не читают терминал.

MPI_Bcast(hash, 41, MPI_CHAR, 0, MPI_COMM_WORLD) рассылает хеш от процесса 0 всем.
Этот вызов делают все процессы, а не только отправитель. Четвёртый аргумент 0 — источник.
В отличие от MPI_2, не нужен отдельный цикл Send и Recv для каждого адресата.

Перебор идёт порциями по 4096 * 9 номеров.
Процесс rank проверяет begin + rank, begin + rank + 9 и так далее.
local — найденный номер либо total, если в своей части совпадения нет.

MPI_Allreduce собирает local со всех процессов, применяет MPI_MIN и записывает
одинаковый answer у каждого. MPI_UNSIGNED_LONG_LONG соответствует типу переменной.
Если кто-то нашёл пароль, его номер меньше total, поэтому он победит при взятии минимума.
Если никто не нашёл, все передали total и общий answer также равен total.

Каждый процесс обязан вызывать Allreduce после каждой порции, даже если уже нашёл пароль.
Нельзя выйти до общего обмена: остальные процессы тогда застрянут в коллективной операции.
Только получив общий answer, все вместе решают продолжить поиск или выйти.
Таким образом отдельная рассылка команды «стоп» не нужна.

Коллективные вызовы идут у всех в одинаковом порядке: Bcast, затем Allreduce по порциям.
В последней порции min не даёт выйти за total. Процесс с пустой частью тоже делает Allreduce.
Найденный пароль по его номеру восстанавливает и выводит процесс 0.
MPI_Finalize завершает работу библиотеки во всех процессах.

ВВОД И ПЕРЕБОР
Группа 501, номер 2: X = 503; X % 3 = 2; M = X % 7 + 3 = 9.
Пароль — ровно 7 символов из 0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ.
Пользователь вводит корректный SHA1 в нижнем регистре; проверок ввода нет.
SHA1 не расшифровывается: сравниваем хеш каждого кандидата с введённым.
Всего 62^7 = 3 521 614 606 208 вариантов. Для номера нужен 64-битный целый тип.
Остаток number % 62 выбирает символ, деление number /= 62 переходит к следующему.
Заполняем пароль справа налево, сохраняя ведущие нули: 0 -> 0000000, 62 -> 0000010.
Полный перебор может занять очень много времени. Примеры используют ранние кандидаты.

ЧТО ПРОИСХОДИТ В SHA1
sha1.hpp реализует SHA1 только для 7 символов этого варианта.
rotate выполняет циклический сдвиг. w[80] — рабочие 32-битные слова.
Семь байтов пароля дополняются битом 1, нулями и длиной 56 бит.
Для такого пароля достаточно одного 512-битного блока SHA1.
80 раундов меняют a, b, c, d, e по стандартным формулам и константам.
Пять итоговых чисел дают 160 бит, которые записываются как 40 hex-символов.
Все рабочие переменные локальные; одновременные вычисления друг другу не мешают.

Справка: https://docs.open-mpi.org/en/main/man-openmpi/man3/MPI_Allreduce.3.html

ПРОВЕРКА
Свежая сборка исходников: без ошибок и предупреждений.
30 основных запусков прошли: 26 на исходной программе, 4 на временных копиях.
Проверены цифры/оба регистра букв в пароле, ведущие нули, все номера работников,
повторные старты и остановки. На временных копиях: пустые части диапазона,
последний кандидат, отсутствие совпадения и верхняя граница ZZZZZZZ.
Полный диапазон из 62^7 вариантов не перебирался; исходный лимит не изменён.
SHA1 сверён с Python hashlib на 5005 строках; ошибок ASan/UBSan нет.
Среда: Open MPI, 9 процессов на Mac. Пройдены границы порций; запуск с 2 процессами отвергается.
Все пары пароль/SHA1 из examples.txt проверены независимо.

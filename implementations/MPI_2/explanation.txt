7. MPI: обмен между парами процессов

КАК РАБОТАЕТ MPI С ОБМЕНОМ МЕЖДУ ПАРАМИ
В tasks2.txt название MPI_2 не раскрыто. Здесь оно трактуется как point-to-point:
обмен данными через MPI_Send и MPI_Recv, без коллективной рассылки/свёртки.
Запускаются 9 процессов командой mpiexec -n 9. Процесс 0 тоже выполняет поиск.
MPI_Init запускает работу MPI, MPI_Comm_rank сообщает номер, MPI_Comm_size — количество.
Если процессов не 9, выполнение завершается через MPI_Abort.

Только rank 0 читает хеш. Он отправляет hash[41] каждому другому процессу:
40 символов SHA1 и завершающий ноль. Остальные получают его через MPI_Recv.
MPI_COMM_WORLD — группа всех запущенных процессов.
Адресат и тег сообщения позволяют отличать разные передачи.
Тег 0 — хеш, тег 1 — локальный результат, тег 2 — общий ответ.

Перебор идёт порциями batch = 4096 * 9 номеров.
Внутри порции процесс rank проверяет begin + rank, begin + rank + 9, ...
password_at переводит номер в семисимвольный пароль.
local хранит найденный номер; значение total означает «в этой порции не найдено».
Даже процесс без совпадения отправляет результат: иначе координатор ждал бы его бесконечно.

В конце порции каждый процесс 1–8 отправляет local процессу 0.
Процесс 0 принимает все восемь значений и берёт минимум вместе со своим local.
Он отправляет общий answer всем остальным. Каждый получает одно и то же решение:
либо продолжать следующую порцию, либо выходить из цикла.
Здесь нет взаимной блокировки: сначала процесс 0 принимает сообщения всех,
потом рассылает ответ; остальные сначала отправляют, затем принимают.

Это проще, чем асинхронные уведомления об остановке, но требует обмена после каждой порции.
Завершение не мгновенное: остальные заканчивают текущую порцию.
Поскольку batch кратен 9, все номера распределены без пропусков.
Последняя порция ограничена min(begin + batch, total).
Процесс 0 восстанавливает пароль по answer и печатает его.
MPI_Finalize завершает работу MPI во всех процессах.

ВВОД И ПЕРЕБОР
Группа 501, номер 2: X = 503; X % 3 = 2; M = X % 7 + 3 = 9.
Пароль — ровно 7 символов из 0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ.
Пользователь вводит корректный SHA1 в нижнем регистре; проверок ввода нет.
SHA1 не расшифровывается: сравниваем хеш каждого кандидата с введённым.
Всего 62^7 = 3 521 614 606 208 вариантов. Для номера нужен 64-битный целый тип.
Остаток number % 62 выбирает символ, деление number /= 62 переходит к следующему.
Заполняем пароль справа налево, сохраняя ведущие нули: 0 -> 0000000, 62 -> 0000010.
Полный перебор может занять очень много времени. Примеры используют ранние кандидаты.

ЧТО ПРОИСХОДИТ В SHA1
sha1.hpp реализует SHA1 только для 7 символов этого варианта.
rotate выполняет циклический сдвиг. w[80] — рабочие 32-битные слова.
Семь байтов пароля дополняются битом 1, нулями и длиной 56 бит.
Для такого пароля достаточно одного 512-битного блока SHA1.
80 раундов меняют a, b, c, d, e по стандартным формулам и константам.
Пять итоговых чисел дают 160 бит, которые записываются как 40 hex-символов.
Все рабочие переменные локальные; одновременные вычисления друг другу не мешают.

Справка: https://docs.open-mpi.org/en/main/man-openmpi/man3/MPI_Send.3.html

ПРОВЕРКА
Свежая сборка исходников: без ошибок и предупреждений.
30 основных запусков прошли: 26 на исходной программе, 4 на временных копиях.
Проверены цифры/оба регистра букв в пароле, ведущие нули, все номера работников,
повторные старты и остановки. На временных копиях: пустые части диапазона,
последний кандидат, отсутствие совпадения и верхняя граница ZZZZZZZ.

SHA1 сверён с Python hashlib на 5005 строках; ошибок ASan/UBSan нет.
Среда: Open MPI, 9 процессов на Mac. Пройдены границы порций; запуск с 2 процессами отвергается.
Все пары пароль/SHA1 из examples.txt проверены независимо.

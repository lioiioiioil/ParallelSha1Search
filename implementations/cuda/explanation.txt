КАК РАБОТАЕТ CUDA
Это параллелизм на видеокарте NVIDIA, а не девять потоков операционной системы.
main выполняется на CPU, функция search с __global__ — на GPU.
По варианту запускаются 9 CUDA-блоков, в каждом 256 потоков: всего 2304 GPU-потока.
Это 9 блоков сетки, а не обещание занять ровно 9 физических SM:
размещение блоков на SM выбирает видеокарта. Число SM программой не задаётся.

search<<<blocks, threads_per_block>>> задаёт сетку запуска: 9 блоков по 256 потоков.
blockIdx.x — номер блока, blockDim.x — число потоков в блоке,
threadIdx.x — номер потока внутри блока, gridDim.x — число блоков.
id = blockIdx.x * blockDim.x + threadIdx.x даёт общий номер 0–2303.
step = gridDim.x * blockDim.x равен 2304.
Поток проверяет begin + id, begin + id + step и так далее до end.
Каждый номер в порции попадает ровно к одному потоку.

GPU использует собственную память. cudaMalloc выделяет место под хеш и ответ.
cudaMemcpy с HostToDevice переносит входные данные с CPU на GPU.
Ответом служит номер кандидата, а total означает «пока не найдено».
Пароль и его хеш — локальные массивы потока: другие потоки их не изменяют.

atomicAdd(answer, 0ULL) атомарно читает общий ответ, не меняя его значения.
Если уже есть найденный номер, поток прекращает работу.
При совпадении atomicMin записывает найденный номер без гонки с другими потоками.
Мы передаём только номер: нет отдельной общей строки и проблемы её частичной записи.

CPU запускает поиск порциями по 1048576 номеров. Это ограничивает работу одного запуска;
реальная длительность зависит от GPU. Порции подряд покрывают весь диапазон.
После запуска cudaGetLastError проверяет ошибку запуска,
cudaDeviceSynchronize ждёт завершения GPU, затем cudaMemcpy копирует ответ обратно.
Следующая порция запускается, только если ответа всё ещё нет.
cudaFree освобождает память. CPU восстанавливает пароль по найденному номеру и печатает.
check сообщает ошибки CUDA; это проверка оборудования/API, не проверка введённого хеша.

В sha1.hpp используются char-массивы вместо std::string, чтобы код выполнялся на GPU.
__host__ __device__ разрешает функцию и на CPU, и на GPU. SHA1 остаётся тем же.
Нужны CUDA Toolkit, nvcc и подходящая видеокарта NVIDIA. На этом Mac их нет:
сборка main.cu и реальный GPU-запуск не проверены. Проверка SHA1 на CPU не заменяет их.

ВВОД И ПЕРЕБОР
Группа 501, номер 2: X = 503; X % 3 = 2; M = X % 7 + 3 = 9.
Пароль — ровно 7 символов из 0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ.
Пользователь вводит корректный SHA1 в нижнем регистре; проверок ввода нет.
SHA1 не расшифровывается: сравниваем хеш каждого кандидата с введённым.
Всего 62^7 = 3 521 614 606 208 вариантов. Для номера нужен 64-битный целый тип.
Остаток number % 62 выбирает символ, деление number /= 62 переходит к следующему.
Заполняем пароль справа налево, сохраняя ведущие нули: 0 -> 0000000, 62 -> 0000010.
Полный перебор может занять очень много времени. Примеры используют ранние кандидаты.

ЧТО ПРОИСХОДИТ В SHA1
sha1.hpp реализует SHA1 только для 7 символов этого варианта.
rotate выполняет циклический сдвиг. w[80] — рабочие 32-битные слова.
Семь байтов пароля дополняются битом 1, нулями и длиной 56 бит.
Для такого пароля достаточно одного 512-битного блока SHA1.
80 раундов меняют a, b, c, d, e по стандартным формулам и константам.
Пять итоговых чисел дают 160 бит, которые записываются как 40 hex-символов.
Все рабочие переменные локальные; одновременные вычисления друг другу не мешают.

Справка: https://docs.nvidia.com/cuda/archive/13.0.0/cuda-c-programming-guide/index.html

ПРОВЕРКА
SHA1 из этого заголовка проверен на CPU: 5005 совпадений с Python hashlib,
без ошибок AddressSanitizer/UndefinedBehaviorSanitizer.
Все пары пароль/SHA1 из examples.txt проверены независимо.
main.cu не собран nvcc и не запущен на GPU. На этом Mac — Apple M4,
NVIDIA GPU и CUDA Toolkit отсутствуют. Для полной проверки нужна другая машина.
Проверка SHA1 на CPU не проверяет CUDA-запуск, атомики GPU и обмен с видеопамятью.

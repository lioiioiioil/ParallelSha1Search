КАК РАБОТАЕТ FORK
Ровно 9 вычисляющих процессов: родитель с номером 0 и 8 детей с номерами 1–8.
Родитель тоже перебирает пароли. Версия предназначена для Mac/Linux.

fork() создаёт новый процесс как копию текущего.
В родителе fork возвращает PID ребёнка, в ребёнке — 0, при ошибке — -1.
Поэтому одна и та же точка программы разделяется на две ветки.
В ветке ребёнка вызываются search(id, shared) и _exit(0).
_exit сразу заканчивает дочерний процесс: он не продолжает цикл создания детей
и не повторяет вывод буферов родительской программы.
Родитель сохраняет PID и идёт создавать следующего ребёнка.

target был прочитан до fork, поэтому каждый ребёнок получает его копию.
Но изменение обычной переменной в ребёнке не изменяет переменную родителя.
Поэтому found и result вынесены в общую память mmap.
MAP_SHARED делает записи видимыми другим процессам, MAP_ANONYMOUS означает,
что отдельный файл не нужен. PROT_READ | PROT_WRITE разрешает чтение и запись.
new (memory) Shared создаёт объект прямо в выделенной области, а не в новой куче.

shared->found — атомарный int. Используются только атомики без внутренних блокировок:
это проверяется static_assert. Для используемых Mac/Linux такая аппаратная операция
работает и с общей областью mmap. Это привязка к этой платформенной реализации,
а не универсальная переносимость std::atomic на любые межпроцессные среды.
exchange(1) выбирает единственного писателя ответа.
Дети видят общий флаг и прекращают поиск после совпадения.

Родитель выполняет search(0), затем waitpid ждёт детей и убирает их записи из ОС.
При прерывании ожидания сигналом (EINTR) waitpid повторяется.
WIFEXITED/WEXITSTATUS проверяют нормальное завершение.
Только после ожидания читается result. Затем вызывается деструктор Shared и munmap.
Если fork не удался, родитель останавливает уже созданных детей и дожидается их.

ВВОД И ПЕРЕБОР
Группа 501, номер 2: X = 503; X % 3 = 2; M = X % 7 + 3 = 9.
Пароль — ровно 7 символов из 0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ.
Пользователь вводит корректный SHA1 в нижнем регистре; проверок ввода нет.
SHA1 не расшифровывается: сравниваем хеш каждого кандидата с введённым.
Всего 62^7 = 3 521 614 606 208 вариантов. Для номера нужен 64-битный целый тип.
Остаток number % 62 выбирает символ, деление number /= 62 переходит к следующему.
Заполняем пароль справа налево, сохраняя ведущие нули: 0 -> 0000000, 62 -> 0000010.
Полный перебор может занять очень много времени. Примеры используют ранние кандидаты.

ЧТО ПРОИСХОДИТ В SHA1
sha1.hpp реализует SHA1 только для 7 символов этого варианта.
rotate выполняет циклический сдвиг. w[80] — рабочие 32-битные слова.
Семь байтов пароля дополняются битом 1, нулями и длиной 56 бит.
Для такого пароля достаточно одного 512-битного блока SHA1.
80 раундов меняют a, b, c, d, e по стандартным формулам и константам.
Пять итоговых чисел дают 160 бит, которые записываются как 40 hex-символов.
Все рабочие переменные локальные; одновременные вычисления друг другу не мешают.

ПРОВЕРКА
Свежая сборка исходников: без ошибок и предупреждений.
30 основных запусков прошли: 26 на исходной программе, 4 на временных копиях.
Проверены цифры/оба регистра букв в пароле, ведущие нули, все номера работников,
повторные старты и остановки. На временных копиях: пустые части диапазона,
последний кандидат, отсутствие совпадения и верхняя граница ZZZZZZZ.
Полный диапазон из 62^7 вариантов не перебирался; исходный лимит не изменён.
SHA1 сверён с Python hashlib на 5005 строках; ошибок ASan/UBSan нет.
Сама программа дополнительно проверена ASan/UBSan: найденный пароль и отсутствие совпадения.
Среда: Apple Clang на Mac.
Все пары пароль/SHA1 из examples.txt проверены независимо.

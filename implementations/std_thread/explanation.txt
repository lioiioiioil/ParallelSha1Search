КАК РАБОТАЕТ STD::THREAD
Это стандартные потоки C++, доступные на Mac, Linux и Windows.
Вместо функции операционной системы используется объект thread.
Главный поток запускает 9 работников, а сам перебор не выполняет.

thread workers[9] сначала создаёт девять пустых объектов, ещё без работников.
thread(search_password, i) запускает search_password(i) в отдельном потоке.
Полученный объект перемещается в workers[i], чтобы затем дождаться этого потока.
Цикл for (auto& worker : workers) worker.join() ждёт каждого работника.
Ссылка & означает, что мы обращаемся к настоящему объекту в массиве, не копируем его.
Сначала созданы все потоки, затем выполняются join — работа идёт параллельно.

Если создание потока выбросило system_error, ставим found = true для остановки
уже созданных работников. joinable() отличает созданный поток от пустого объекта.
Дожидаемся созданных, печатаем ошибку и выходим. Это нужно потому, что разрушение
объекта thread с неотработавшим join приводит к аварийному завершению программы.

После нормального завершения всех join печатаем общий результат.
Поиск назван search_password, чтобы имя не путалось со стандартной std::search.

ОБЩИЙ ФЛАГ ОСТАНОВКИ
atomic<bool> found безопасно читается и изменяется несколькими потоками.
found.exchange(true) возвращает прежнее значение: первый нашедший получает false
и записывает result, остальные не записывают. У каждого работника свой password.
Главный поток читает result только после завершения работников: сам флаг ещё
не гарантирует, что строка результата полностью записана.

ВВОД И ПЕРЕБОР
Группа 501, номер 2: X = 503; X % 3 = 2; M = X % 7 + 3 = 9.
Пароль — ровно 7 символов из 0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ.
Пользователь вводит корректный SHA1 в нижнем регистре; проверок ввода нет.
SHA1 не расшифровывается: сравниваем хеш каждого кандидата с введённым.
Всего 62^7 = 3 521 614 606 208 вариантов. Для номера нужен 64-битный целый тип.
Остаток number % 62 выбирает символ, деление number /= 62 переходит к следующему.
Заполняем пароль справа налево, сохраняя ведущие нули: 0 -> 0000000, 62 -> 0000010.
Полный перебор может занять очень много времени. Примеры используют ранние кандидаты.

ЧТО ПРОИСХОДИТ В SHA1
sha1.hpp реализует SHA1 только для 7 символов этого варианта.
rotate выполняет циклический сдвиг. w[80] — рабочие 32-битные слова.
Семь байтов пароля дополняются битом 1, нулями и длиной 56 бит.
Для такого пароля достаточно одного 512-битного блока SHA1.
80 раундов меняют a, b, c, d, e по стандартным формулам и константам.
Пять итоговых чисел дают 160 бит, которые записываются как 40 hex-символов.
Все рабочие переменные локальные; одновременные вычисления друг другу не мешают.

ПРОВЕРКА
Свежая сборка исходников: без ошибок и предупреждений.
30 основных запусков прошли: 26 на исходной программе, 4 на временных копиях.
Проверены цифры/оба регистра букв в пароле, ведущие нули, все номера работников,
повторные старты и остановки. На временных копиях: пустые части диапазона,
последний кандидат, отсутствие совпадения и верхняя граница ZZZZZZZ.
Полный диапазон из 62^7 вариантов не перебирался; исходный лимит не изменён.
SHA1 сверён с Python hashlib на 5005 строках; ошибок ASan/UBSan нет.
Сама программа дополнительно проверена ASan/UBSan: найденный пароль и отсутствие совпадения.
Среда: Apple Clang на Mac.
Все пары пароль/SHA1 из examples.txt проверены независимо.
